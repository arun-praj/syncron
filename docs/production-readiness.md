# Chrome launch readiness — 22 September 2026

Target: Saturday, 26 September 2026. This pass covers Chrome, YouTube, and the current Node/Docker backend. Firefox and other providers are outside this pass. No production deployment is authorized by this document.

## Working method

The planning agent traces each failure and supplies Luna High with the affected flow, root cause, minimal fix, and acceptance checks. Luna implements one issue at a time. The planning agent reviews the diff and reruns relevant checks independently. Existing working-tree changes are preserved. An issue is not verified merely because Luna reports completion.

## Baseline

- Node 24.21.0: 47 tests pass across seven files; typecheck passes.
- Lint fails on three unused symbols in popup/App.tsx and RoomScreen.tsx.
- Chrome is now connected. The browser tool blocks chrome://extensions; waiting for a normal YouTube page with the installed Syncron sidebar to identify and exercise the build.
- Docker smoke starts a healthy container but fails signup with HTTP 403. Installed Better Auth checks Origin when Node fetch supplies Fetch Metadata headers; the smoke request omits Origin. Confirm this with the corrected request before classifying it as an application failure.

## Release gates still required

- Full tests, typecheck, lint, Chrome production build, and Docker smoke on the final tree.
- Rendered Chrome signup, OTP, onboarding, login, logout/account switch, and password recovery/change.
- Two distinct users: create/invite/join, play/pause/seek/rate/audio, permissions, host transfer/leave/end, reload/reconnect, and expired membership.
- Chrome device permission denial and autoplay denial, hide/reopen, fullscreen, chat/reactions, and tab closure.
- Real production HTTPS/WSS endpoints, published extension ID/trusted origins, deliverable email, LiveKit connectivity, database backup/restore, and hosting topology must be verified against the actual deployment. The checked-in Docker stack is a development stack; readiness checks alone do not establish internet launch readiness.
- Requirements mention unfinished Google OAuth and fuller moderation/fullscreen UI. These are feature gaps rather than verified regression fixes; launch scope must explicitly account for them.

This is a living inventory of discovered issues, not a claim that all possible bugs have been found.
